TL;DR

  • Undergraduate teaching machine: metal Cartesian gantry, wood take/replace boards, jaw gripper — not an SMT chip shooter.
  • A photograph of a drawn schematic is classified into six symbols (V, C, GND, D, R, L), written as LTspice .asc, then mapped onto bins the arm can visit.
  • Three brains: Raspberry Pi 4 (vision), Arduino Mega 2560 (motion), ESP32 (Wi-Fi jog). IR remote is a third jog path.
  • Honest speed: about 40–70 components per hour as coded. Z travel is most of the cycle. Desktop OpenPnP is ~15× faster; factory SMT is ~1000×.
  • This page is the 2026 packaging. The 2022 report, photos, firmware, and demos stay in Drive and private GitHub.

Abstract

SECB is a one-semester computer-engineering machine that treats circuit assembly as pick-and-place. The operator photographs a schematic. Software on a Raspberry Pi segments ink, reads handwritten digits, classifies six component classes, and exports an LTspice netlist. A Mega 2560 then homes three steppers against limit switches, picks a part from a 20-bin take grid, and drops it on a replace grid — optionally rotating the wrist 74° for vertical parts. The project was built under Arduino-class controllers, a student budget of more than 4,000 NIS, and a four-month calendar. It is a laboratory for vision, serial protocols, and Cartesian kinematics, not a substitute for OpenPnP or a Yamaha mounter. This page rewrites that work as a survey so the machine can be studied, simulated, or rebuilt in Vancouver without standing next to the original frame.

Pipeline

Two coordinate systems never mix. Vision lives in a 640×640 pixel page and an LTspice sheet. Motion lives in millimetres from the home corner of a wooden table.

  1. Load a JPEG. Resize to 640×640.
  2. OCR digits first so numbers are not mistaken for parts.
  3. Threshold, skeletonize, pair endpoints into parallel strokes → voltage source, capacitor, ground.
  4. Erase wires with a line-segment detector. Remaining blobs go to HOG + SVM → diode, resistor, inductor.
  5. A three-stage GUI lets a human delete, add, or relabel boxes.
  6. Remaining ink becomes nodes. Each part is snapped to LTspice pin pitch and written as .asc.
  7. A planned parser was supposed to emit start N take place take place … on USB 9600. That glue is unfinished.
  8. The Mega homes, then runs take_a_piece and a horizontal or vertical place.

Vision

Entry point: schematic_generator.py in the Circuit-Solver repo. The detector is two families, not one network.

idxPartHow it is found
0voltage sourcetwo parallel skeleton strokes, length ratio > 1.2
1capacitortwo strokes, ratio 1.0–1.2
2groundthree parallel strokes
3diodeHOG + SVM label 0, then +3
4resistorSVM label 1 + 3
5inductorSVM label 2 + 3

Digits use a Keras MNIST model on 32×32 Canny blobs. Nearby digits (distance ≤ 50 px) merge into multi-digit values. A value box within 100 px of a part becomes SYMATTR Value. Units such as k, µ, Ω are not parsed.

The geometry + HOG-SVM core follows the open-source circuit-recognizer / Automatic-Circuit-Recognition line. SECB added value OCR, an LTspice writer, and the machine handoff. pylsd on the Pi was the painful dependency.

Motion

Source of truth is Drive final_project, not the early GitHub sketch. Enable pins sit LOW. Servos must run from an external 5 V supply or USB serial dies.

AxisDIR / STEP / ENLimit
X42 / 44 / 4630
Y23 / 25 / 2732
Z43 / 45 / 4734
Rotate servopin 24, 74°
Gripper servopin 26, 20°

One cycle is 8 mm = 1600 microsteps. XY pulses at 1 kHz → 5 mm/s, X then Y, no acceleration. Z is faster and travels 18 cycles (144 mm) every down or up.

$$r = \lfloor p/5 \rfloor,\quad c = p \bmod 5,\quad x_{\mathrm{take}} = 9.5 - r\cdot 2.5,\quad y_{\mathrm{take}} = 13.4 + c\cdot 6.8$$

Take slots are 0…19. Horizontal place uses a 9-wide index and a +1.6 mm half-piece offset on Y. Vertical place uses a 10-wide index, a −1.6 mm offset on X, and the 74° wrist.

Home order: Z, then X, then Y. Each axis creeps until its switch reads LOW five times.

Serial and other ports

Three control paths share the same mechanics.

1. Job protocol — Pi → USB 9600

start      ...

parse_raspberry_input() is an empty stub. The commented production loop reads one space-separated line with Serial.readString(). The flashed sketch ignores serial and plays a hardcoded demo (take 10 / place H 5 / take 12 / place V 3 / …). replace_decoded(), which should pick horizontal vs vertical from the schematic angle, is commented out.

2. Wi-Fi jog — browser → ESP32 HTTP → UART 115200

Routes: /x_up /x_down /y_up /y_down /z_up /z_down /gr_op /gr_cl. The ESP32 prints ard1 x_up and friends. Jog step is ~0.1 mm on XY and ~0.25 mm on Z. SSID credentials in the 2022 sketch are not reproduced here.

3. IR jog — NEC remote on Mega pin 6

Eight button codes plus hold-repeat 0xFFFFFFFF. Quirk: jog firmware drives the rotate servo for “gripper open/close,” not the gripper servo.

The Drive parser zip prints wires and values from a hardcoded .asc. It does not emit the start N … line. Vision and motion are finished islands. The bridge is not.

Timing

Factories quote CPH. This firmware quotes blocking seconds.

$$\mathrm{CPH} = 3600 / T_{\mathrm{cycle}}$$

One pick-and-place is four 144 mm Z strokes plus a 5 mm/s XY tour. Z is ~70% of the cycle. A representative part is ~50–90 s → about 40–70 CPH before homing. That sits next to careful hand stuffing, not next to a chip shooter.

ClassTypical tactCPH-ish
SECB as coded~50–90 s~40–70
Hand place, easy passives~20–40 s~90–180
LumenPnP / desktop OpenPnP~2–4 s~900–1,600
Flexible factory mounter (IPC-9850 chips)~0.08–0.12 s~30k–45k

Industrial machines do not win by pulsing an A4988 harder. They delete the long Z, pick several parts per XY tour, and overlap vision with flight. Raising delayMicroseconds on this frame mostly loses steps.

Hardware A–Z

Mechanics

  • Welded metal skeleton, wood base, two wood boards (take left, replace right).
  • 6 mm timing belt, ~4 m; 16-tooth pulleys. Measured 32 mm of belt per motor revolution.
  • Gripper on a rail that rides the gantry. Later notes mention a magnet + relay as an accuracy experiment.

Actuators and power

  • Steppers: 2× J-5718HB2401 + 1× J-5718HB3401 (NEMA-23 class).
  • Drivers: 3× YS-DIV268N / A4988-class, 1 kΩ series resistors on DIR/STEP/EN so USB does not drop.
  • 2× S3003 servos on a separate 5 V PSU. 12 V PSU for the steppers.
  • 3× door-style limit switches with ezButton pull-ups.

Computers

  • Arduino Mega 2560 — motion master. Owns every stepper and servo.
  • Raspberry Pi 4 — vision host. Any laptop works; the Pi was chosen because it is portable.
  • ESP32 — HTTP jog endpoint. SoftSerial to Mega pins 10/11.

Original student cost: more than 4,000 NIS. Build photos and three demo clips (14 Jan 2023) live in the Drive archive linked above.

What works, what does not

Finished

  • Homing on three limits
  • Take 0–19 and H/V place
  • USB job grammar
  • Wi-Fi and IR jog
  • Six-class recognizer + GUI correction
  • .asc export

Unfinished

  • Empty parse_raspberry_input()
  • Commented replace_decoded()
  • Parser does not emit start N
  • Flashed loop is a demo sequence
  • Jog “gripper” moves the wrist
  • No vacuum sense, no soft limits beyond dest < 0

Simulate the whole job without the frame

No single website draws the gantry, sells the bolts, routes the PCB, compiles the Mega sketch, and places 0402s. Use a stack. That is how this kind of machine is taught now.

LayerToolWhat you get
1. VisionExisting Circuit-Solver in VS Code or ColabJPEG → boxes → .asc on any laptop. No robot.
2. Firmware + wiringWokwi (browser + VS Code extension)Mega 2560, ESP32, steppers, serial console. Jog the job string before you buy silicon.
3. Job-level PnPOpenPnP built-in machine simulatorFeeders, bottom camera, job planner. Closest thing to “SMT without a machine.”
4. MechanicsOnshape (free cloud) or FreeCADFrame, rails, pulley stack. Browser CAD, no Fusion seat required.
5. Electrical / PCBKiCadDriver wiring, 1 kΩ series resistors, PSU split. EasyEDA if you want LCSC parts immediately.
6. Optional 3D plantWebots or CoppeliaSimOnly if you want a moving twin. Overkill for this syllabus.
Recommended teaching path. Run vision on a sample JPEG first. Port final_project into Wokwi and prove start 1 10 5 homes and prints the debug line. Open OpenPnP’s simulator to feel what a real job planner does with feeders. CAD the frame last, after the protocol is boring.

Wokwi already has public Mega + multi-stepper CNC sketches. GRBL itself is a poor Wokwi guest (timer edge cases). Bit-bang firmware like SECB is a good guest. OpenPnP remains the right answer if the goal shifts from “replay 2022” to “learn SMT.”
